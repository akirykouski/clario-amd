# Clario HTTP API (contract)

Shapes: `backend/clario/models.py`. One codebase, two modes: `CLARIO_MODE=patient` (port 8765, runs on the patient's device) and `CLARIO_MODE=clinic` (port 8800, runs on the clinic's AMD server). JSON unless noted.

## Both modes
| Method | Path | Returns |
|---|---|---|
| GET | `/api/health` | `Health` (`mode`, `llm: {backend (offline-fixtures\|amd-token-factory\|amd-vllm\|ollama-local\|local\|openai-compatible), model, base_url_host, is_amd (true for amd-vllm and amd-token-factory)}`, `ontology: {terms, diseases}`, `demo_instance: bool`, `clinic_url: string or null` (env CLARIO_CLINIC_URL, the Share page default), `review: {threshold, source (conformal\|env\|override), alpha, delta, calibration_n, calibration_status}`) |

Lab rows carry `confidence` (self-consistency across samples when the client has `samples`, else the model's own) and `review`: `auto` or `needs_review` (confidence below `CLARIO_REVIEW_THRESHOLD`, default 0.7). Env: `CLARIO_DOC_CONCURRENCY` (default 4, 32 for remote backends, `LLM_CONCURRENCY` on Token Factory), `CLARIO_DOC_SAMPLES` (3; 1 on Token Factory), `LLM_VISION_MODEL` (else `LLM_MODEL`), `LLM_OCR_MODEL` (default `MinerU2.5-Pro` on Token Factory, `off` disables). With an OCR model a page is read by `POST {LLM_BASE_URL}/ocr` into markdown; a recognised result table is read in code (`CLARIO_DOC_STRUCTURE=table`, default, model `MinerU2.5-Pro`; odd cells get confidence 0.5), else `LLM_MODEL` copies the table into JSON (`CLARIO_DOC_STRUCTURE=model` forces this, model `MinerU2.5-Pro + Gemma-4-31B-IT`); a row whose name or numbers are not in the OCR text is `needs_review` (confidence at most 0.5), and the collection date is read from the OCR text in code. If the OCR call fails the page image goes to the vision model. Both calls are in the call log (purpose `document`; the OCR record has `images: 1`, `redacted: false`).

`Entity.review` is the single state field: `auto` (extracted, not looked at), `needs_review` (self-consistency confidence below the threshold: flagged for the clinician, optional for the patient), `confirmed`, `corrected`, `rejected` (decided by a person). Extraction v3 also fills `family_history`, `onset_hint` and `confidence` (null when not measured). `onset_hint` holds only a phrase that says when it started ("since Tuesday", "da tre giorni"): a time of day ("in the morning", "la sera") or a trigger ("after the sun", "dopo il sole") is dropped in code (`clario/onset.py`) and the entity gets the flag `onset_dropped`. Technical flags (`hpo_dropped`, `no_hpo`, `onset_dropped`) are never shown to the patient; the clinic's check list shows the HPO reason. Every entity except `rejected` counts toward patterns and leaves the device in a share (`models.COUNTED`); `models.REVIEWED` = `confirmed`, `corrected`.

`ReviewItem = {kind: "entity" \| "lab", id, entry_id, canonical, display, value, confidence, source_excerpt, quote, hpo_label, occurred_on, negated, family_history}`. Lab items add `{flag, page, batch_id, unit, ref_low, ref_high}` (`entry_id` null, `value` = printed value with unit) and use the same `POST /api/review/lab/{id}`: `correct` takes `value` as free text (`5,5` or `Positivo 1:160`), the flag is recomputed in code. Other modules add a kind by registering a handler in `app.state.review_kinds` (see `review.py`); the lab handler is registered by `doc_routes.py`.

`SafetyNotice = {level: "emergency" \| "advice", message, matched}`: returned when the text matches a red-flag rule. Emergency text still saves, but the UI must show the notice first.

Extraction env (patient mode): `CLARIO_SC_N` (self-consistency samples, default 5, 1 disables), `CLARIO_TRUST_MODEL_CONFIDENCE=1` (use the model's own `confidence`), `CLARIO_HPO_PICK` (default 1: second call picks the HPO id from ontology candidates only), `CLARIO_REVIEW_THRESHOLD` (default 0.7).

`SharedEntity` carries `id` (the entity id, which the clinic keys its decisions on), `family_history`, `onset_hint`, `reviewed`, `confidence` and `needs_review`; the clinician brief marks items with `needs_review=true` as "low-confidence reading, please check", and the clinic screen lists them for a confirm or reject. A relative's condition leaves the device only as family history: `family_history=true` and no `hpo_id`, so it is never a patient term and never counted. Negated entities keep `negated=true` and are not counted either.

`SharePackage.labs: SharedLab[]` is lab history, not just the period: every result (up to the end date) of each test that appears in the shared period, plus any out-of-range result (flag low or high, or a positive text result) from the 12 months before the end date, so an earlier positive ANA or high anti-dsDNA stays visible next to a later negative. Every row except rejected ones; rows nobody looked at carry `reviewed=false`, low-confidence rows carry `needs_review=true` (the brief and the clinic screen say "low-confidence reading, please check"). `SharedLab = {id, test_name, test_key, name_en, value_numeric, value_text, unit, ref_low, ref_high, flag, abnormal, date, page, entry_id, reviewed, confidence, needs_review, decision}`; `test_name` is as printed, `name_en` is the English name of a known test (the English clinic UI shows it), `test_key` groups one test across documents, `entry_id` is the diary entry of the import, the diary entry that holds the import (lab lines cite report pages, not this entry). `flag` (`low`, `high`, `normal`, `positive`) is computed in code (`documents.compute_flag`): a number against its printed range, or for a qualitative result positive/present/reactive (any titre) -> `positive` (out of range, `abnormal`), negative/absent/non-reactive -> `normal`; null when there is nothing to compare with (a number with no printed range is never "normal"). `decision` (`confirmed`, `rejected` or null) is filled by the clinic server for rows that needed a check. `POST /api/demo/documents` moves the newest synthetic report to 28 days ago so the demo labs fall inside a normal share period.

## Privacy (both modes)
Text is pseudonymized (`backend/clario/privacy.py`) before a model call when `CLARIO_PSEUDONYMIZE=1`, or by default in patient mode when `LLM_BASE_URL` is not localhost. Email, phone, codice fiscale, IBAN, absolute dates, street addresses, full dates of birth and personal names (recognised by title, label, relation, first-name list or "X said" pattern) become `[EMAIL]` `[PHONE]` `[CODICE_FISCALE]` `[IBAN]` `[DATE]` `[ADDRESS]` `[NAME]` `[HEALTH_ID]` (tessera sanitaria) `[RECORD_NO]` (hospital record number). Rules and a first-name lexicon do this with no model involved. `PrivacyReplacement.type` keeps its seven kinds: `[HEALTH_ID]` and `[RECORD_NO]` report as `codice_fiscale`. The measured miss rate is in `eval/results/pii_leak.json` (10.8% of identifiers on a strictly held-out synthetic test half; 5.8% after fixes chosen by reading test failures; n = 712). Scanned images and photos are sent unredacted. Medical terms, doses, lab values and scores are untouched. Quotes returned by the model are mapped back to the original text (the map lives in memory for the call). Every call is logged on every backend, redacted or not: patient mode in the vault (kind `ai_call`), clinic mode in `ai_calls.jsonl` in the clinic data dir.

## Safety interceptor, wording and storage
- Red-flag text and dosing or medicine-change questions (EN and IT: "can I take more ibuprofen", "should I stop my pills", "posso aumentare la dose", "smetto di prendere ...?", and any such question about medicines in pregnancy or breastfeeding) are matched in `safety.check_entry` before any model call. Emergencies return `level=emergency`. Dosing questions return `level=advice`, point to the clinician or pharmacist, and the entry skips extraction. A note that merely mentions a medicine is not blocked.
- Patient-facing server text honours `lang=it`: safety notices, `/api/patterns` (labels, note), `/api/patterns/next-question`, the saved answer entry (`Risposta a una domanda: ... Sì|No`). HPO names in Italian come from `clario/data/hpo_it.json` and `lay_terms_it.json`; a term without an entry keeps its English label. Italian next questions are only asked for terms that have an Italian phrase.
- Clinic mode stores the opened packages sealed to the clinic key (as received) and writes briefs and the call-log previews encrypted with AES-256-GCM under a key derived (HKDF) from the clinic key file. No diary text is written to disk in clear.
- One extraction prompt: `backend/clario/prompt.py` is a verbatim copy of `train/prompt.py` (a test fails if they differ); the app sends the same system prompt and a single user turn as training. No few-shot.
